Case study · graduation project

NeuroQuant

A PyTorch framework, published on PyPI, that compresses neural networks to INT8 or mixed INT4/INT8 precision and exports real, deployable ONNX models.

pip install neuroquant
7quantization methods
3objectives: accuracy, size, latency
39Python modules, about 19.7K lines
v2.1on PyPI, with a docs site

The problem

Deep models are expensive to run on edge and production hardware. Many academic quantization tools only simulate low precision, optimize one objective at a time and ignore real latency. NeuroQuant was designed to produce real INT8 artifacts and to search the trade-off between accuracy, on-disk size and measured latency.

How it works

  • Sensitivity analysis. A per-layer Hessian-diagonal or empirical-Fisher score ranks how fragile each layer is to quantization.
  • Evolutionary search. A from-scratch NSGA-II (non-dominated sorting, crowding distance, sensitivity-weighted mutation) assigns INT4 or INT8 to every Conv and Linear layer, keeping the first and last layers at INT8.
  • Surrogate-assisted. A gradient-boosting model trained on real evaluations ranks hundreds of candidates per generation, so only the most promising ones are actually quantized and measured.
  • Seven quantizers. PTQ with KL and MSE calibration, QAT with BN folding and distillation, GPTQ, SmoothQuant, AWQ, SmoothQuant→GPTQ and AdaRound.
  • Deployment fidelity. Static INT8 ONNX export (QDQ format) that reports the real file size and ONNX Runtime latency, backed by a per-layer latency lookup table.
  • Analysis. Hypervolume and knee-point selection, Pareto plots, bit-width heatmaps, Grad-CAM and SHAP for interpretability, MLflow tracking and a self-contained HTML report.

Engineering

A YAML-driven CLI pipeline plus a library API, Pydantic-validated configuration, deterministic seeding and resumable checkpoints, pytest smoke tests on a GitHub Actions matrix (Ubuntu and Windows, Python 3.10–3.12), and MkDocs documentation.

Case study · information retrieval

NutriQuest

A domain search engine and chatbot for fitness and nutrition, built for Zewail City's Information Retrieval course.

525documents, 428 unique URLs
35curated topics
3sources: Wikipedia, YouTube, Google
~306Kwords of indexed page text

The problem

Fitness and nutrition advice is scattered across Wikipedia, YouTube and the open web, its quality varies, and general-purpose search does not know the domain vocabulary.

How it works

  • Data. 35 curated topics × 3 sources × top-5 results, giving 525 records with links and scraped text.
  • Preprocessing. NLTK tokenization, stop-word removal and Porter stemming, applied identically to documents and queries.
  • Retrieval. A PyTerrier index ranked with BM25 and TF-IDF.
  • Query expansion. Pseudo-relevance feedback: frequent informative terms from the top BM25 hits are added to the query, which is then re-run.
  • Re-ranking and diversity. Term-match scores weighted by source quality, with per-source quotas so results mix Wikipedia, YouTube and Google.
  • RAG chatbot. The top-5 BM25 documents become the context for an LLM answer through the OpenRouter API, scoped to fitness and nutrition.
  • Evaluation code. Precision, recall, F1 and NDCG@k implemented from scratch.

Interface

A Streamlit app with a custom dark theme, source filters, topic browsing, dataset statistics and an admin panel.

Team

Two-person course project with Mostafa Nashaat.

Real-Time Sentiment Analyzer & Reporter

A near-real-time pipeline that turns raw customer feedback into sentiment labels and LLM-written management reports, with no paid APIs.

97.25%test accuracy
0.97macro-F1
62,509held-out test reviews
625Klabelled reviews in the corpus

Results on the held-out set

The problem

Cafés and restaurants collect free-text feedback faster than staff can read it. The goal was to label every new review automatically and turn batches of reviews into reports a manager can act on.

Pipeline

  • Model. An embedding layer initialised from GloVe 300-d and fine-tuned, a bidirectional LSTM(128), batch normalization and dropout. 25.5M parameters, trained on 625,094 labelled reviews.
  • Ingestion. The app reads a Google Sheet every 30 seconds, processes only new rows and saves its position so it resumes after a restart.
  • Reporting. Once enough new reviews arrive, a local LLM (LLaMA 3 or DeepSeek-R1 via Ollama and LangChain) writes a four-part report: executive summary, sentiment analysis, key themes and recommendations.
  • Export. Markdown to HTML to a styled A4 PDF with WeasyPrint, downloadable from the Streamlit UI.

Case study · classical ML

IoT Intrusion Detection

Detecting and categorizing malicious IoT network traffic from 21 numeric flow features, on a dataset where one class outnumbers another 109 to 1.

938,583network flows
6traffic classes
109:1largest-to-smallest class ratio
0.84best macro-F1

The problem

DDoS makes up 73% of the flows while MITM and Recon are under 1% each, so accuracy alone is misleading. The models were judged on macro-F1 and per-class recall.

What we did

  • Data audit. No missing values; 96,187 duplicate rows (10.2%) found and removed in the main pipeline.
  • EDA. Distributions, box plots and a correlation analysis that exposed redundant feature pairs.
  • Pipeline. RobustScaler, SelectKBest feature selection and SMOTE applied to the training split only, to avoid leaking synthetic samples into evaluation.
  • Models. Random Forest (200 trees), XGBoost (300 trees, depth 7) and LightGBM, including a DART variant.

Results

ModelSetupAccuracyMacro-F1
XGBoostStandardScaler, no resampling0.9110.84
Random ForestRobustScaler + SelectKBest + SMOTE0.8580.82
LightGBMRobustScaler + SelectKBest + SMOTE0.8590.81
LightGBM DARTIQR clipping0.8590.67

Each approach used different preprocessing; the best XGBoost run kept duplicate rows. The SMOTE-balanced Random Forest kept recall at or above 0.71 for every class, and the main remaining error was confusing DoS with DDoS.
